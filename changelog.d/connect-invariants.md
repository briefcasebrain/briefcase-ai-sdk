### Changed
- Config writers (`connect`, `mcp install`, `policy init`/`off`, `--undo`, `--managed`) enforce their guarantees in one place each. A file is changed only by inserting text (a one-line JSON file stays one line; undo removes only what was written, byte for byte), and only while it still holds what the preview saw: a file created in between is refused, never overwritten. Previews show only the lines that would be added; nothing read from an existing file or tool registry is printed. Ownership of a TOML table is by name over its parsed content (a trailing newline, spacing or a table the tool inserted does not make it "modified"), and a registered MCP command is owned only when the tool's own registry reports exactly the command that was registered, in the profile it was recorded for; an unreadable registry is "unknown" and never "ours", and a same-named entry is looked for before every add (Codex and VS Code replace one silently).
- `connect` refuses, naming the key (never its value), when the tool's settings already enable content capture or hold an OTLP credential that would combine with the new endpoint, unless `--capture-content` or `--headers` is passed. Hooks always carry their endpoint explicitly, so `BRIEFCASE_RECEIVER_ENDPOINT` cannot redirect them. `CLAUDE_CONFIG_DIR` and `CODEX_HOME` are honoured for every write, policy hooks included; a profile variable that cannot be resolved is refused. A plan with a failing target (other settings than a connected target has, an unsafe write) writes nothing, and a dry run exits with the status the real run would.
- `policy init --force` never replaces a policy file that `policy init` did not write; `policy init` does not say "already installed" unless the hooks are on disk; `policy off` exits 1 and says enforcement is still on when it cannot remove a hook, and keeps its record. `connect --managed --force` replaces only files an earlier pack wrote (by manifest hash) and refuses a directory that holds anything else; pack files that hold supplied credentials are created 0600 and the endpoint in the Cursor hook is shell-quoted.
- `connect --undo` prints a registration's removal command qualified with the profile it was recorded for, only after checking the registry still holds exactly that registration. `connect status` reports a Codex block whose tables changed as drifted.
- Every connect, policy and undo command holds one advisory lock for its whole run, so two of them never lose each other's ownership records. A write still compares the file just before the atomic rename; an editor saving in that few-millisecond window can still race, because no operating system gives better without the tool's cooperation.
- Existing keys in a tool's whole telemetry namespace (Claude: every `OTEL_*` and `otel*` setting; VS Code and Gemini: their telemetry settings; Codex: the `[otel]` table) block a first connect, naming the keys, unless this invocation writes them itself. Files keep their line endings (CRLF included), a JSON file with duplicate keys is refused, undo refuses to remove a TOML table when the surrounding text would not parse back identically, and a file that receives a supplied credential ends up 0600. Supplied secrets are redacted from every message, including a refused snippet and a failing subprocess's output.
- Enforcement hooks fail closed on every failure path under `--fail-closed`, whichever entry point runs them. The ambient `BRIEFCASE_RECEIVER_TOKEN` is sent only to a loopback receiver or to the URL in `BRIEFCASE_RECEIVER_TOKEN_ENDPOINT`.
- Fail-closed hooks (`--fail-closed`) deny anything that is not a fully valid event the policy explicitly allows: malformed or incomplete input, an unknown event, an empty path set, a failure to write the verdict (exit 2). Managed packs bind each hook to the exact system policy by hash (`--require-policy-sha256`) and deny when it is missing or different rather than falling back to a weaker policy. `policy init --fail-closed` refuses where the hook could not start (missing launcher, interpreter or `briefcase-ai`, or a Claude Code version without the failure setting). Hook reporters never follow redirects, and the receiver token goes only to the default local receiver or the URL in `BRIEFCASE_RECEIVER_TOKEN_ENDPOINT`.
- Fail-closed hooks parse strictness first and on its own (an option without a value cannot swallow `--fail-closed`), deny an unknown tool, an empty command and a missing event name, judge a managed hook's required system policy from the exact bytes that were hashed and deny whenever it is missing or changed (also without `--fail-closed`), and leave with the host's blocking status 2 even when stdout is a closed pipe (Python would otherwise exit 120). `policy init --fail-closed` refuses where the installed Claude Code version cannot be read, and for Codex (which starts the hook command itself, so a missing executable cannot be blocked) unless `--accept-codex-startup-risk` is passed; `connect --managed` with a `fail_closed` policy does the same.
- The first-connect check also covers variables already exported in the process, the Windows managed-settings files and registry value and the macOS managed-preferences plist; a layer that exists but cannot be read or understood counts as a risk. A Claude registration whose argument boundaries Claude's own `.claude.json` or `.mcp.json` does not show is unknown in every scope, and undo never suggests removing an unknown registration. The registration is journalled before the add runs. Retry hints print only the leading command words, never an argument, and a Basic credential is masked whole. `policy off` removes only the hooks that were named in its confirmation.
- Fail-closed hooks also deny a `WebFetch` without a URL, an MCP call that does not name a server and a tool, a relative path with no working directory in the event, and a nonempty shell command that yields nothing to judge; a hook bound to a required policy blocks when its bookkeeping, its verdict write or the hook itself fails, and writes its reason to stderr first. `policy off` binds its confirmation to the files and entries it displayed and says so when hooks that were not part of it remain. First-connect also covers Claude's `ENABLE_BETA_TRACING_*` and `BETA_TRACING_*` settings, the Windows user registry value and an unlistable managed directory, re-checks the layers and environment after confirmation, and keeps the MCP record when a failed add may have committed.
- Fail-closed hooks also deny a blank URL or MCP identity, a relative working directory, and a shell command with no usable working directory (its relative file references cannot be judged); a hook that carries `--require-policy-sha256` blocks from the portable CLI's and the isolated launcher's outer handlers too, and a required hash that is empty or not a sha256 digest denies instead of skipping authentication. The Codex acknowledgement lists exactly what `--fail-closed` covers and what it does not. First-connect lists managed drop-ins again at write time, and `policy off` with nothing displayed removes nothing.
