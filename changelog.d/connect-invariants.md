### Changed
- Config writers (`connect`, `mcp install`, `policy init`/`off`, `--undo`, `--managed`) enforce their guarantees in one place each. A file is changed only by inserting text (a one-line JSON file stays one line; undo removes only what was written, byte for byte), and only while it still holds what the preview saw: a file created in between is refused, never overwritten. Previews show only the lines that would be added; nothing read from an existing file or tool registry is printed. Ownership of a TOML table is by name over its parsed content (a trailing newline, spacing or a table the tool inserted does not make it "modified"), and a registered MCP command is owned only when the tool's own registry reports exactly the command that was registered, in the profile it was recorded for; an unreadable registry is "unknown" and never "ours", and a same-named entry is looked for before every add (Codex and VS Code replace one silently).
- `connect` refuses, naming the key (never its value), when the tool's settings already enable content capture or hold an OTLP credential that would combine with the new endpoint, unless `--capture-content` or `--headers` is passed. Hooks always carry their endpoint explicitly, so `BRIEFCASE_RECEIVER_ENDPOINT` cannot redirect them. `CLAUDE_CONFIG_DIR` and `CODEX_HOME` are honoured for every write, policy hooks included; a profile variable that cannot be resolved is refused. A plan with a failing target (other settings than a connected target has, an unsafe write) writes nothing, and a dry run exits with the status the real run would.
- `policy init --force` never replaces a policy file that `policy init` did not write; `policy init` does not say "already installed" unless the hooks are on disk; `policy off` exits 1 and says enforcement is still on when it cannot remove a hook, and keeps its record. `connect --managed --force` replaces only files an earlier pack wrote (by manifest hash) and refuses a directory that holds anything else; pack files that hold supplied credentials are created 0600 and the endpoint in the Cursor hook is shell-quoted.
- `connect --undo` prints a registration's removal command qualified with the profile it was recorded for, only after checking the registry still holds exactly that registration. `connect status` reports a Codex block whose tables changed as drifted.
- Every connect, policy and undo command holds one advisory lock for its whole run, so two of them never lose each other's ownership records. A write still compares the file just before the atomic rename; an editor saving in that few-millisecond window can still race, because no operating system gives better without the tool's cooperation.
- Existing keys in a tool's whole telemetry namespace (Claude: every `OTEL_*` and `otel*` setting; VS Code and Gemini: their telemetry settings; Codex: the `[otel]` table) block a first connect, naming the keys, unless this invocation writes them itself. Files keep their line endings (CRLF included), a JSON file with duplicate keys is refused, undo refuses to remove a TOML table when the surrounding text would not parse back identically, and a file that receives a supplied credential ends up 0600. Supplied secrets are redacted from every message, including a refused snippet and a failing subprocess's output.
- Enforcement hooks fail closed on every failure path under `--fail-closed`, whichever entry point runs them. The ambient `BRIEFCASE_RECEIVER_TOKEN` is sent only to a loopback receiver or to the URL in `BRIEFCASE_RECEIVER_TOKEN_ENDPOINT`.
