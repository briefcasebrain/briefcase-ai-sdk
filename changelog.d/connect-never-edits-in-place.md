### Changed
- `briefcase-ai connect`, `briefcase-ai mcp install` and `briefcase-ai policy init` never modify a file entry, TOML block or tool registration that already exists. A target they wrote that is still exactly as written is reported as already connected. Asking for other settings (`--endpoint`, `--headers`, `--capture-content`, a different `--scope`) changes nothing, exits 1 and says to run `briefcase-ai connect --undo <tool>` (or `briefcase-ai policy off`) and connect again. A target that was changed or removed since is no longer treated as briefcase's and is left as it is; one that briefcase did not write is skipped and its contents are never printed. `--undo` removes only what still matches what was written and reports the rest. Content capture is on only for a target that `--capture-content` wrote in that run, and the warning prints when it is written.
- The connect journal (`~/.briefcase/connect/journal.json`) has a new schema version. A journal from a pre-release build is not read: `connect`, `connect --undo` and `mcp install` change nothing, list what that build recorded and tell you to remove it by hand and delete the journal.
