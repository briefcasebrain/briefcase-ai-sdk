### Changed
- Engine lifecycle: the recorded current release is the one whose server runs. "Is release X running" is decided by the engine project's server container (its image id against X's record), not by a label a shared sidecar carries. An upgrade restarts and switches in one lock interval, treats any docker error as a failure that leaves the old release current, and keeps the installed TLS setting unless `--tls` or `--no-tls` is passed; an install next to a running release leaves that release current.
- `engine up` and an upgrade's restart start containers only when every volume they would mount is positively known to be this engine's or absent; an inspection that fails blocks. `engine uninstall` stops before deleting anything when docker cannot say what runs or `compose down` fails, and `--purge` deletes the secrets only after every engine volume is confirmed absent (docker missing or failing blocks; `--force-without-docker` is accepted only for an install that never created volumes).
