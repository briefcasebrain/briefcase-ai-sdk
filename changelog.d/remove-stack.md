Supersedes: "`briefcase-ai stack`: use `briefcase-ai engine` (one release)."

### Breaking
- `briefcase-ai stack up|down|status|logs` is removed, with the bundled GHCR compose file and `compat.json`: the engine is installed from a signed bundle with `briefcase-ai engine install` and run with `briefcase-ai engine up|down|status|logs`. `briefcase-ai doctor` no longer lists registry images (`briefcase-ai engine doctor` checks the installed ones), `briefcase-ai run logs` reads the installed engine's verdict-worker logs (and says so when the release has none), and `BRIEFCASE_OCIJJ_COMPOSE` is no longer read. From a running 4.4 stack: stop it with `docker compose -p <project> down` (the project is `oci-jj` unless you named it; `engine up` and `engine doctor` print the project they find), then `briefcase-ai engine install` and `briefcase-ai engine up`. There is no data transfer: the new engine starts empty and the old data volumes are left in place until you remove them with `docker volume rm`. `engine up` refuses to start while a Compose project other than the engine's own runs an `oci-jj-server` service. It also refuses when a volume it would mount (`briefcase-engine_pgdata`, `_miniodata`, `_regdata`) exists without the `ai.briefcase.engine` label it puts on the volumes it creates, which is the case for a 4.4 stack started with `-p briefcase-engine`; it prints the `docker volume inspect` and `docker volume rm` commands, and nothing is mounted until you remove or relabel them.
