Supersedes: "`briefcase-ai stack`: use `briefcase-ai engine` (one release)."

### Breaking
- `briefcase-ai stack up|down|status|logs` is removed, with the bundled GHCR compose file and `compat.json`: the engine is installed from a signed bundle with `briefcase-ai engine install` and run with `briefcase-ai engine up|down|status|logs`. `briefcase-ai doctor` no longer lists registry images (`briefcase-ai engine doctor` checks the installed ones), `briefcase-ai run logs` reads the installed engine's verdict-worker logs (and says so when the release has none), and `BRIEFCASE_OCIJJ_COMPOSE` is no longer read. Migration from a running 4.4 stack: `docker compose -p oci-jj down`, then `briefcase-ai engine install` and `briefcase-ai engine up`; the new engine starts empty and the old data volumes (`oci-jj_*`) are kept, not migrated, until you remove them with `docker volume rm`. `engine up` refuses and `engine doctor` warns while the old stack runs.
