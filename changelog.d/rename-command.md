### Breaking
- The command is `briefcase-ai` (was `briefcase`) and the MCP server command is `briefcase-ai-mcp` (was `briefcase-mcp`), so `uvx briefcase-ai` and `pipx run briefcase-ai` work. The Python import name `briefcase` and the `BRIEFCASE_*` variables are unchanged and there is no alias for the old names. Migration, in this order: (1) replace `briefcase` with `briefcase-ai` in scripts, CI and shell aliases; (2) on each machine run `briefcase-ai connect` (replaces the Cursor hooks and MCP entries 4.4 wrote, keeps the endpoint you set earlier) and `briefcase-ai policy init` (replaces enforcement hooks that still call `briefcase hook`, which fail open once the old command is gone; repeat any `--fail-closed` or `--portable` you used); (3) for a fleet, regenerate each managed pack with `briefcase-ai connect --managed --out DIR` and the original options, then redeploy it: packs already deployed keep calling `briefcase hook`; (4) run `briefcase-ai status` and `briefcase-ai doctor --connect`, which report any hook or machine-wide managed pack that still names the old command. `briefcase-ai connect` leaves an MCP server named `briefcase` alone unless this SDK registered it.
